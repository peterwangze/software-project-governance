# 项目 Profile 规则

Profile 约定记录深度和参与角色。循环层级由目标、风险与交付单位决定，每一次放行都需能够定位到本轮证据。

| Profile | 适用场景 | 实际要求 |
| --- | --- | --- |
| lightweight | 个人项目、探索、内部工具 | 用最小可重放的验收操作与原件记录本轮结果；触及产品交付或发布时保留适用的独立确认。 |
| standard | 团队交付 | 完成的工作绑定证据，记录关键取舍、风险、缓解责任及复审。 |
| strict | 关键系统、多团队和合规项目 | P0 交付须有至少两条独立证据，风险量化且有明确责任人；退出条件仍有疑义或阻断项时保持待验。 |

## 角色与证据

协调者负责目标和授权。内层修改由开发者或治理开发者执行，独立审查者核实结果。广度较小的项目可以合并准备工作与角色调度；同一人编写的工件仍须由另一执行主体独立验收。涉及系统设计、测试计划、契约、发布或外部反馈时，按工作单元的真实缺口选对应角色。按角色读取 `references/loop-role-mapping.md`。

## 切换

将用户认可的档位、原因、适用范围写入项目配置及决策记录。提高强度时补齐仍待验工作的证据；保留已作出的裁决、原件及未解问题。触发模式（always-on、on-demand、silent-track）决定呈现时机。
