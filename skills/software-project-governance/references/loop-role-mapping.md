# 独立审查与循环

协调者派发稳定单元 ID、任务、层、Gate、轮次、目标、验收操作与工件。审查者独立验证本次尝试，返回能复核的结论；修改由所属循环的实现角色承担。适用规则随工件交给审查者，运行状态由 `loop status --unit <id>` 读取。

| 审查技能 | 本轮职责 |
| --- | --- |
| `requirement-review` | 立项 G1 核实原始意图；准备 G2 核实用户与调研依据。 |
| `design-review` | 在准备条件或交付设计入口 G5 复核接口、替代方案及本轮设计风险。 |
| `tech-review` | 按准备 G3 或交付设计 G5 的实际问题复核候选试用、技术约束和取舍。 |
| `code-review` | 在内层 G6 沿真实调用方验证本轮改动，缺陷退还实现者。 |
| `test-review` | 在内层 G7 独立重放用户路径与失败样本，结果交给上级交付的验收者。 |
| `release-review` | 显式发布单元（`release_version`）在中层 G8、G9 由 Release Reviewer 核对保护、候选版本、回滚和当次授权。普通交付目标（`delivery_goal`）在 G9 消费独立成品验收者按冻结契约出具的回执。 |
| `retro-review` | 在外层 G10、G11 复核使用反馈及可验证的改进，形成下一轮目标。 |

## 裁决与复审

- `APPROVED` 表示指定工件满足本轮验收条件。`APPROVED_WITH_NOTES` 须有独立结构字段 `unresolved_blockers=0`，所有备注均可追查。缺失、非零、非法或重复矛盾值应拒绝。
- `NEEDS_CHANGE` 及兼容输入 `NEEDS_CHANGES` 触发所属单元返工。标出失败输入、预期与实际、位置及影响，修正后发起下一轮独立复审。
- `BLOCKED`、未知结论、无充分证据或无法独立审查时保留阻断。遇到熔断或范围/风险决策交由协调者升级。
- `review-record` 持久保存审查依据。Gate 只可消费与当前任务、单元及轮次匹配的回执；验收者在恢复后可复读相同状态。Check 30 核查审查链连续性及终态。正式签核、用户发布授权和业务结果均沿各自的证据记录。
