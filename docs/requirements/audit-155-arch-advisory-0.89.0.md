## 一、决策摘要（顾问原文要点）

**建议：B（结构切换）作为目标架构，采用「单一权威、限期过渡、宿主级分批切换」实施；补齐目标驱动契约；A/C 不作为终态。**

四点核心判断：
1. 诊断基本成立，但「结构必然性」需限定——足以解释线性诱导，尚不能证明所有行为偏差由该因素决定或 B 能完整消除偏差
2. **根因应上移一层**：不是单纯「loop 没进提示词」，而是**生命周期语义的权威链没有切换**（数据/判定/协议/呈现四层仍共同维护 classic）；注入缺失与运行时零数据是该迁移未完成的两个结果，不宜分主次
3. B 是必要方向但**现有 B 不是充分方案**——把 stage/Gate 换成 tier/round/lane 只解决状态模型，不能自动实现「以项目最终目标为导向」；否则从「为了过 Gate」变成「为了退出 loop」
4. 最大风险不是改动文件多，而是**「名义 loop、实际仍由 classic 或未经验证数据决定动作」的假切换**——会重演 0.65.0 问题并增加用户信任风险

## 二、对根因诊断的修正意见

- 根因表述建议改为：**「DEC-097 的语义迁移停留在能力交付层，未完成宿主激活与权威链切换；classic 仍通过数据、判定、协议和呈现闭环塑造 agent 行为」**
- 最强证据不是词频，而是**有效权威一致指向 classic**（激活模式/判定主体/热数据坐标/协议语义/运行时闭环五项，结构面 §2.1/C-01/C-09 + 行为面 H1/H2/R2/R4/R6/R8）
- 「结构必然性 ≠ 行为必然性」：成立的是系统必然提供 classic 主坐标；未证明的是行为占比与切换后目标导向自然成立——无需等行为实验才承认架构欠账，但必须用行为实验判断修复效果
- H2 证伪范围应收窄：排序代码无显式 Gate 键 ≠ 推荐系统整体无 Gate 偏置（上游：候选池是否多由 Gate 缺口生成、priority/version 是否由阶段模型赋值、无 Gate 映射的高价值工作能否入池、失值任务是否因已登记而持续被推荐）

## 三、双报告遗漏的关键因素（顾问补充）

1. **最大遗漏：缺少可执行的「目标—行动—证据」契约**——新模型如何识别对项目最有价值的下一步。建议 bootstrap 主层级：当前有效目标及版本 → 目标差距/风险/不确定性 → 推荐行动及预期贡献 → unit 与 loop 上下文 → 适用护栏/授权/证据缺口。**目标在前，工作与反馈居中，Gate 在约束位置**。无需新建目标引擎——execution packet 已含 goal/acceptance_contract/quality_budget，先接通既有契约。
2. **agent 代理激励可能仍错误**：当前「过门/完成任务/继续推荐」组合奖励可见合规活动而非项目价值；**必须允许「暂不新增动作」「终止低价值 unit」「等待必要证据」为正当推荐**——高效率不等于永远制造下一项工作
3. **Gate 数量不是首要问题，适用范围与证据有效期才是**；per-unit lane 也可能变成「每 unit 一条小瀑布」——lane 不能天然承担全序推进语义
4. **流程根因更深一层**：交付验收验证了资产、没有验证采用——「能力实现 → 宿主激活 → 默认路径可达 → 执法生效 → 行为验收 → 持续运行证据」应成为未来架构决策的完成条件链

## 四、三候选评估

| 候选 | 顾问评价 | 适用边界 |
|---|---|---|
| A 投影重解释 | 可改善可见性，不解决权威冲突；先宣传 loop 而执行仍 classic 可能制造虚假能力感 | 限期观测/受控实验/迁移准备，**不作终态** |
| B 结构切换 | 唯一与目标架构一致的候选；须加入目标契约、证据有效性与行为验收 | **推荐终态** |
| C 混合渐进 | 原描述内部不清晰：「lane 为权威」但「判定权威不动」分裂了状态权威与执行权威 | 仅允许重写为**有退出条件的迁移步骤** |

**对 C 的重要纠正**：只读兼容视图 ≠ 双模型 ≠ 必然双写——Gate 表若完全由新权威单向生成、不可人工修改、不参与动作决策，则只是兼容投影。C 的真问题是 classic 仍决定行动资格。同理 B 保留 classic compatibility preset 时必须明确其角色（只读解释器/迁移适配器/可执行模型）。

## 五、实施路径（五步——顾问建议）

1. **先定义语义与权威，不先翻 registry**：紧凑 ADR（目标/unit/loop/Gate/版本关系、事实源与派生视图、Gate 适用范围与证据有效期、unit 缺失或歧义处理、classic 兼容边界与退役条件）；注意 loop 拓扑 registry ≠ 完整检查策略——区分拓扑、检查策略与运行状态权威
2. **隔离副本完成本仓全链迁移**：dry-run → 人工核对 unit 划分 → apply → 成功认证 → 失败迭代 → 中断恢复 → 并发写入 → 回滚演练；不接受「运行时文件生成了」作为验收；**错误 unit 锚定比缺失锚定更危险**，自动推断只适用唯一可解释匹配，歧义时要求确认
3. **打通一条完整纵向切片**：目标 → unit → 行动 → 验证 → 认证/迭代 → 事件落盘 → bootstrap 投影 → 新会话恢复；同步该切片注入文本/热数据/验证器；不要先改全部文案再等执行层
4. **按宿主/一致性边界授权切换**：复用分族授权票机制；新模型接线完整性可先 WARN，但安全/质量/授权底线不随之降级；关键运行数据缺失时不自动退回 classic 继续执行敏感动作
5. **行为级验收与退役**：固定场景多独立新会话对照（紧急修复不重做前序/多 unit 并行/Gate 失败继续修而非宣告阶段失败/目标变更取消任务/证据不足暂不发布/无 Gate 映射的高价值探索/运行时缺失或歧义）——**不用「出现 loop 词汇」或「next_gate 已删除」替代行为验收**

## 六、被低估的风险与报告缺陷（顾问指出）

1. **回滚能力表述过强**：配置回滚/初始迁移回滚/产生新事件后的回滚/外部副作用后的补偿是四件不同的事——后两者可能需前向修复而非恢复旧文件；禁止旧备份覆盖切换后有效审计记录
2. **C-10 应列为切换前置风险**：证据检查空转意味着新投影可能只是更漂亮地展示不可信状态；证据应与 unit/产物版本/策略版本/审查主体绑定
3. **三方矛盾表述过强**：外部原型验证通过与本仓未激活**可以同时为真**——真问题是验证范围/激活范围/文档时效没有清晰表达
4. **RB-2 的「A/C 不依赖激活、天然免疫」有误**：C 明确含本仓迁移，不免疫宿主激活风险（此项已在 R1 复审背景中转交 Design Reviewer 记录）
5. 文件数/测试数不足以评估成本——应按契约消费点/宿主类型/入口平台/profile/恢复路径/副作用边界建矩阵；性能上应用有版本和新鲜度标识的增量投影而非每次重放完整事件史

## 七、第四路径：目标驱动控制面

**目标驱动决策控制面 + loop 工作组织 + 按动作生效的 Gate 策略**（三层职责分离：目标层=为什么做/优先做什么/何时调整或停止；loop 层=如何组织尝试/反馈/学习/重新规划；Gate 层=什么动作必须满足什么条件）——不是 A/B/C 之外的第四套并存模型，而是 **B 应采用的职责划分**。近期从既有 execution packet 与推荐依据入手。

## 八、最终意见（顾问原文）

支持「DEC-097 未在有效运行路径落地」的核心诊断；不支持把「loop 结构切换」直接等同于「目标导向问题已解决」。

建议授权：**以 B 为目标架构，以单一判定权威为约束，先完成本仓端到端纵向切片，再按宿主和契约边界分批激活；兼容面只读、限期退役；将目标贡献、证据可信度与行为效果纳入完成条件。**

最终验收问题：「当项目目标、风险和实际状态变化时，它是否选择了更合理的工作；既不会为了过门制造工作，也不会以持续演进为由绕过必要护栏。」
