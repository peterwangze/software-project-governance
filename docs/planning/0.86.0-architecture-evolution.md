## 0. 设计公理与实证基座

**DEC-220**：确定性行为（schema 约束/状态翻转/记录追加/序列编排/门禁执行/量测）MUST 软件化；LLM 只推进不确定逻辑（triage/审查判断/风险评估/异常处置/用户交互/开发本身）。

**实证**（2026-09-19 会话）：机录 CLI 路径零事故（×20+ 操作）vs LLM 手工路径 5 次事故（R0 审查时点——3 表格行锚定错/1 锁 JSON schema 错/1 决策行截断；审查后追加第 6 次：DEC-220 行首截断，同型）——全在确定性区，全被门禁或复检捕获。审计根因：**校验器先行于写入器**——软件能发现手工错误但没提供不用手工的路径。

**公理正确读法**（审计结论，双顾问认可）：封闭规则集操作软件化 · 开放语义判断 LLM 化 · 判断结论用确定性 schema 持久化。

## 1. 目标架构（双源收敛版）

**确认既有六层架构为正式目标**（组合根 registry.py 已是雏形；archguard R1/R2 已数学单调化收缩）——不发明新框架，完结已建一半的架构并命名。

```
L6 组合根（registry + CLI entry）→ L5 引擎壳（verify_workflow 收缩至 dispatch+gate 聚合）
→ L2~L4 领域模块：存储域（.governance 规范源+事件日志）· 状态机域（phase-legality+纯转移）
   · 投影域（markdown 再生+drift check）· 迁移域（plan-hash 恒等）· 判断外壳域（verdict schema+引用解析+后果派发）
→ L1 数据资产（只读事实源）→ L0 contracts（形状定义，零依赖）

LLM Coordinator 残留职责（封闭枚举）：①判断→schema 化 verdict ②用户交互 ③开发本身 ④引擎不可自分类异常的人工裁决
Coordinator 不再做：手写治理记录 · 闭环序列编排 · 状态解释
```

**完工判据（量化版，外部源补强）**：被接管流程中 LLM 手写治理记录数=0；并量测——每票确定性环节 LLM 往返数↓ · 闭环耗时分项（等待判断/等待外部）· 首次写入成功率 · 冲突/重试/投影漂移/人工恢复次数 · 故障恢复零重复追加零丢失。

## 2. 双源裁决合议（第二轮交叉验证）

### 2.1 收敛面（两源一致——直接采纳）

| 裁决点 | 合议结论 |
|---|---|
| 迁移总纲 | **写入器先行，存储分离后置**（本地第一轮「存储先行」正式修订；外部源「先封手写入口再逐表迁移」同向）——最缺的是写入路径不是存储形态 |
| 并发语义 | **CAS+锁组合非对立**（loop_paro_engine L524 实证：per-file lock 串行化 CAS 临界区）；M7.6a 任务锁保留为业务锁（认领/TTL/去重），CLI 内文件锁保护 READ→VALIDATE→COMPUTE→WRITE 临界区 |
| 闭环失败语义 | **前向恢复（断点续传），拒绝跨 git/push 边界的整体回滚**；幂等必须 effect-based（查世界不信日志——resume 先核实际效果再补步）；任务完成/闭环完成/发布完成三事实分离 |
| 事件载体 | 复用 loop_event_log 模块机器（零第二实现），**独立 closure 日志文件**（分域不混入）；日志作审计+恢复上下文（恢复可读，日常状态查询走状态库） |
| 双轨协议 | **按步骤粒度声明**：某步 CLI 化落地即 MUST CLI；CLI 不可用=fail-closed 升级（不回落手写）；引擎全不可用=degraded-but-honest（判断照常、记录 BLOCKED 响亮披露+emergency-append 隔离区） |
| 判断外壳 | 枚举 verdict+证据锚+后果派发；**证据引用存在性=确定性区**（显式参数窄口径机检，不扫正文）；正文语义留 Reviewer；边界问句「两合格评审者是否可能合理不同意」入审查纪律 |
| 机录 DoD | 写入器 CLI 强制交付物清单（见 §4）——CLI 也会回归（键碰撞/GBK/缺行三次历史实证），面积乘数下不许「写入器先行于守护测试」复演根因 |
| commit/push | 链终点输出 ready-to-commit 摘要+message 建议，`--finalize` 显式门；git 副作用边界：禁 `add -A`（限定产物路径+暂存区并发检查）、push 目标来自受控配置、禁 force-push、凭据零记录 |

## 3. 0.86.0 主题一句话

**「四类可靠原子写入器 + 一条可恢复标准闭环 + 接管范围内零手写」**——不是全面 JSON 化+全流程自动化。发布前真实任务演练：每个持久化/git 边界中断并恢复，证明不丢记录、不重复追加、不误提交旁路文件、不因 push 失败回滚业务事实。

## 4. 机录写入器 DoD（强制清单）

0. **模型输出不可信**：入参类型/边界检查；投影转义；URL 不自动抓取
1. **写前完整验证**：先算候选结果再校验 schema+跨记录约束
2. **幂等与冲突协议**：同 operation_id 重试返回原结果；同 ID 不同输入拒绝；effect-based 幂等声明
3. **可靠落盘**：显式 UTF-8/同文件系统临时文件/原子替换/声明支持平台
4. **写后重读自检**：同一 schema re-read+validate（禁第二 schema 定义）
5. **dry-run+结构化结果**：预览 diff；区分校验失败/冲突/可重试/需介入
6. **恢复路径**：中途失败可修复或重入，不留只能手改的半成品；多文件时显式「源已提交/投影待修复」态（禁 commit，重入只重建投影）
7. **守护测试**：键碰撞/GBK/缺行/重复执行/并发覆盖/崩溃点/特殊字符/legacy 数据各 ≥1 negative-control（threading 先例 test_loop_paro_engine L871）
8. **渐进启用+降级契约**：按记录类型接管；behavior_profile 回退的是采用姿态非 schema 严格性；kill-switch 退回原子 CLI 非手写
9. **机器来源标记**：每条机器写入行自标识（Check 30c 模式渐进 FAIL 族）
