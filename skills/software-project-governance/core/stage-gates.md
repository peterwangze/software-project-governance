# 工作单元的 Gate 检查目录

选择与本工作单元和本轮交付有关的条款。数量、阈值和验收操作沿用该单元的成功契约与质量预算。阶段名是活动词汇。当前适用的门和返工动作可用 `loop status --unit <id>` 查看。

## G1 — 立项裁决

- **必审材料**：原始目标、拟交付的成品和用户或授权人的决定。
- **检查项**：
  1. 对齐谁实际使用、怎样验收、当前授权覆盖的范围。关键取舍由有权限的人确认。

## G2 — 调研依据

- **必审材料**：影响本次决定的事实来源、样本或候选调查结果。
- **检查项**：
  1. 关键判断能回到真实来源，仍未知的限制有明确的补验动作。

## G3 — 选型依据

- **必审材料**：候选、实际试用记录和所需约束。
- **检查项**：
  1. 在相同输入和宿主约束下重跑关键行为。排除不适用候选须有依据。

## G4 — 环境就绪

- **必审材料**：当前宿主的运行方式、依赖和实际输出。
- **检查项**：
  1. 下一位执行者能运行本次验收所需的入口。真实环境依赖 CI、容器或凭据时验证该依赖。

## G5 — 设计契约

- **必审材料**：生产者、消费者与成品验收者共同使用的接口、样例及约束。
- **检查项**：
  1. 核实数据语义、失败条件和恢复边界。重大架构或跨边界决策由独立审查者复核，收到阻断返回设计。

## G6 — 修改验收

- **必审材料**：当前修改、原始失败样例、约定命令的实际结果或本轮独立代码审查。
- **检查项**：
  1. 重放该单元关心的行为。正式审查或受保护提交核实独立记录及对应候选。约定质量阈值随本次契约检验。

<a id="g7--成品复验"></a>

## G7 — 成品复验

- **必审材料**：实际入口、输入、预期与观察，及本轮受影响的集成边界。
- **检查项**：
  1. 重放原失败样本和用户路径。并行子项集成后在父目标验证组合结果。失败返回责任单元，再回本门复验。

## G8 — 发布保护

- **必审材料**：拟发布候选绑定的构建及本次部署需要的保护措施。
- **检查项**：
  1. 重跑受影响的 CI 或部署条件。验证坏输入被拦截，确认能根据实际健康信号停止或恢复。

## G9 — 交付出口

- **必审材料**：目标的冻结契约、实际制品与独立验收回执；显式发布另核版本、候选签核与用户授权。
- **检查项**：
  1. 普通 delivery_goal 由独立验收者逐条核实本次实际制品和未结子项，可信失败退回修正并复验。DSH 使用原生完成入口，其他宿主可用 `goal-bridge --action accept-delivery --goal <id>`。
  2. 显式 release_version 由 Release Reviewer 签核同一候选，用户的发布授权和可用恢复方式须覆盖目标环境。

## G10 — 运营反馈

- **必审材料**：实际反馈原件、受影响的成品和观察条件。
- **检查项**：
  1. Release 核实影响并将问题交给能修正它的单元，提供样本和回验方式。时效或观察窗口依据约定。

## G11 — 改进复核

- **必审材料**：原问题、已采取的改进与后续观察。
- **检查项**：
  1. 复验原问题和改进效果，未收敛风险保留责任人和返回点；需用户接受风险时取得实际裁决。

## Gate 执行原则

1. 每次判断绑定单元、层级、轮次及证据。未满足条件时返回相应循环迭代。
2. Gate 结论必须能回溯到证据和事实源
3. 任何 agent 适配都不得绕过 Gate 规则
4. Gate 检查可以由 agent 自动执行（可程序化部分）或由用户确认（需人工判断部分）
5. 返工须对同一验收条件重放失败样本并复审，保留此前回执。
6. 关闭单元前，核对对用户承诺的后续事项；保留相应任务、责任人与验收条件。
7. 对当前修改、交付或反馈执行适用的方向、质量、体验审计。阻塞项返回责任单元；独立复审消费修复后的工件和原失败样本。
8. 对需要用户裁决的风险接受、范围变化或发布授权，协调者通过 AskUserQuestion 传达影响与可选动作，保存实际授权。
