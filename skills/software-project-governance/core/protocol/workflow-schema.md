# 跨宿主工作流协议

各宿主用同一项目根、安装技能和工作单元 ID 接续事务。项目状态由 `governance-bootstrap --format json` 的 `loops` 和 `loop status --unit <id> --json` 提供。

| 对象 | 身份与含义 | 消费方 |
| --- | --- | --- |
| 目标 | 用户原话、成品、可复验的验收条件 | 协调者据此建立工作单元，独立验收者据此检验成品 |
| 工作单元 | 稳定 ID、所属循环、父单元、当前尝试和待执行动作 | 宿主恢复本单元，工作者记录计划、行动、观察和反思 |
| 领域活动 | 调研、设计、开发、测试、发布、运营等可复用方法及工件 | 按本轮问题选用的 agent 和 skill |
| Gate | 本单元当前条件与独立回执相符时，允许相应动作 | 执行引擎处理放行、原处补证、返工或升级 |
| 证据 | 真实输入、原始观察、工件位置、审查者、所属单元及轮次 | 复审者重放失败样本，父单元消费已解决的子项 |
| 决策与风险 | 范围、责任人、风险接受、依赖及回访条件 | 协调者和用户处置需要授权的问题 |

[运行协议](../lifecycle.md)列出原生命令，[循环拓扑](../loop-engineering-registry.json)定义门与返工位置。
