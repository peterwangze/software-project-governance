# 测试与质量保障 — 子工作流

## 独立使用时的目标锚定

从用户原始需求和当前验收契约确定可观察的成功与失败条件。使用治理的项目从 `.governance/plan-tracker.md` 及当前工单取得范围、质量预算和所需的独立验收。独立调用时可使用用户给出的验收条件及仓库原生测试入口。目标有实质冲突时，派发的 QA 把冲突交回 Coordinator，由其与用户裁决并记录。

## 选择验证范围

- **单项验收或缺陷回归。** 从用户实际调用的界面、CLI 或 API 验证期望结果，再选择会改变结论的失败或边界输入。修复类任务优先用同一输入在旧版本观察缺陷、在新版本观察修复，并复验相关既有行为。无法取得旧版时说明该限制。
- **正式测试阶段。** 核对 G6 已通过或条件通过、测试计划和开发门禁回执。按项目 profile 和质量预算准备测试计划、测试报告、缺陷清单及质量评估。沿关键调用链核验模块间的接口契约，检查成功返回与错误处理是否符合调用方预期。测试范围包含立项时承诺的用户价值，已有 PR/FAQ 时逐项对照。
- **用例取舍。** 根据实际接口和失败影响选择空输入、并发、超时、异常恢复等适用情形；如契约指定了边界清单，须逐项覆盖。优先检验最终工件、持久化状态或用户可见结果。测试能够在已知错误条件下失败，才能用它区分预期行为与回归。用测试替身隔离外部依赖时，说明尚未验证的真实边界。

## 量化判定

对每项必测指标写明目标、单位、统计口径和比较方向，优先复用本项目的基准命令、测试工具或 CI 回执。例如，延迟 p95 的上限以毫秒判定，吞吐量下限以每秒请求数判定。按契约原有的不等号和允许偏差比较；区间目标同时核对上下界。同一测试中一项达标不能抵消另一项必测指标失败。

对相对基线的要求，核对基线与本次的输入、负载、环境、单位及统计量在同一口径；记录样本量与实测值。缺少必需基线、负载不一致或采样不足时，报告已测事实和比较缺口。绝对目标可按自身口径独立核验。项目要求性能或安全证据时，功能用例通过不足以签收这些项目。

## 产出物标准与退出条件

在已有报告或工单回执中，把每个验收条件对应到输入、预期、实测和原始证据。回归汇总分列运行、通过、失败、跳过数量；必测项跳过或未运行时保留缺口。已观察到的未达标结果记录为失败。确实不适用的项目标注理由；调整范围或接受例外需按既有授权办理。

测试发现附复现入口、用户影响和严重级别。阻塞或关键缺陷须由用户确认严重级别，调整该级别也须用户确认；记录根因、修复和复验结果。派发的 QA 通过 Coordinator 提请确认并交回结果。接受已知风险或绕过 Gate 均由用户裁决，独立调用本技能时也须取得该裁决。

## Gate 映射

完整 **G7 — 测试通过** 的四项判据与必审材料以[阶段门禁](../software-project-governance/core/stage-gates.md#g7--测试通过测试--防护网与-cicd)为准。逐项核对关键及阻塞缺陷为零、要求的回归套件 100% 通过、各性能指标达到目标范围、安全测试覆盖关键风险且无高危漏洞（HIGH/CRITICAL）。按项目已约定的专项要求补齐材料，记录尚无证据的必测项，再由有权角色裁决。
